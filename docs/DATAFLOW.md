# Data flow and code map

Generated by `Rscript tools/make_docs.R` from `pipeline.R` and the files of `R/`; do not edit by hand. Run from the project root: `Rscript tools/run_all.R` runs the steps in order, and a script can also be run on its own once the scripts it reads from have run.

## 1. Which script reads and writes what

| # | Script (`analysis/`) | Reads | Writes (`results/`) | Used in |
|---:|:---|:---|:---|:---|
| 01 | `01_fit_all.R` | CSV recordings (`data/`) | `config_used`, `fit_prcp`, `fit_fantasia`, `fit_exercise`, `df_population_summary`, `population_summary.csv` | Fit and innovation diagnostics; time constants (Figure S10) |
| 02 | `02_simulation_recovery.R` | (simulated) | `sim_recovery` | Recovery under known truth (Figure S1) |
| 03 | `03_identifiability.R` | CSV recordings (`data/`) | `identifiability` | Results 1-2 (Figure 1, Table 3) |
| 04 | `04_sensitivity.R` | CSV recordings (`data/`) | `sensitivity` | Sensitivity, prior contrast (Figure S2) |
| 05 | `05_prcp.R` | CSV recordings (`data/`), `fit_prcp` | `prcp` | Result 3: tilts and stand-ups, negative control, pressure response, lagged correlation, dose-response, responses by maneuver (Figure 2; S6 to S8) |
| 06 | `06_fantasia.R` | CSV recordings (`data/`), `fit_fantasia` | `fantasia` | Result 4: group contrasts, stability, respiration and baroreflex (Figure 3; S9) |
| 07 | `07_recovery_benchmark.R` | (simulated) | `recovery_choice` | Recovery definition (Figure S3) |
| 08 | `08_event_detection_validation.R` | (simulated) | `event_detection` | Event detection (Figure S5) |
| 09 | `09_exercise.R` | `fit_exercise`, `recovery_choice?` | `exercise` | Result 5 (Figure 4; S6) |
| 10 | `10_hrv_comparators.R` | `fit_prcp`, `fit_fantasia`, `fit_exercise`, `prcp?`, `exercise?` | `hrv` | HRV comparators |
| 11 | `11_supplement_checks.R` | `fit_prcp?`, `fit_fantasia?`, `fit_exercise?` | `supp_checks` | Bound, calibration, equivalence checks (Figure S4) |
| 12 | `12_preprocessing_checks.R` | (simulated) | `prep_checks` | Data-preparation checks (earlier vs current format, cleaning gate) |
| 13 | `13_figures.R` | every `results/*.rds` that exists | `figure_info`, `{figures}`, `manuscript/figures/*` | All figures (look and examples: `cfg$figures`) |

A name ending in `?` is optional: the step uses the result when it exists. `Rscript tools/run_all.R --list` prints the same, `--status` says which steps are fresh or stale.

Every analysis script has the same four parts: **Load**, **Analyse every recording** (or simulate), **Combine and summarise**, **Save**. The per-recording steps live in `R/steps/`; the scripts only call them.

## 2. Where the functions are (`R/`)

`R/load.R` loads the layers in this order; a layer may use the layers before it.

### `R/core/`: helpers every other file may use

**`core/io.R`**: reading the CSV recordings written by tools/prep-data.R  
`check_data_path`, `fantasia_group`, `clean_sample`, `read_recording_rows`, `rri_time_alignment`, `resolve_rr_source`, `build_rr_series`, `usable_covariates`, `read_recording`, `window_rec`, `has_covariate`, `load_dataset`, `read_prcp_events`

**`core/stats.R`**: statistical helpers  
`exact_ci`, `cliffs_delta`, `group_contrast`, `loo_r2`, `loo_auc`, `km_median`, `icc_consistency`, `paired_comparison`, `spearman_table`

**`core/utils.R`**: small helpers used everywhere  
`log_msg`, `ensure_dir`, `write_result`, `read_result`, `id_seed`, `with_seed`, `map_recordings`, `is_err`, `median_range`, `format_median_range`, `pick_subset`, `bind_results`, `drop_failed`, `column_available`, `field_or_na`

### `R/model/`: the model, its fits and the simulator

**`model/fitting.R`**: the reported fits: one recording or a whole dataset, with the engine  
`fit_model_fast`, `as_rec`, `fit_recording`, `fit_dataset`

**`model/identifiability.R`**: is the latent decomposition identified by RR alone?  
`draw_start_params`, `theta_from_start`, `run_multistart`, `count_solutions`, `trajectory_dispersion`, `ident_metrics`, `profile_surface`, `identifiability_analyse_recording`, `identifiability_summarise`

**`model/model_variants.R`**: the model specifications M0-M3, built on the unmodified engine  
`load_fast_filter`, `has_cpp`, `filter_eval`, `model_spec`, `drop_term`, `prepare_series`, `unpack_theta`, `default_theta`, `variant_objective`, `fit_variant`, `fit_specs`, `variant_hessian`

**`model/simulation.R`**: generative simulator of the SPARK model (OU drives -> integrate-and-fire phase) with deterministic drive profiles that mimic perturbations  
`simulate_rr`, `prof_step`, `prof_exercise`, `drive_from_angle`, `angle_protocol`, `rsa_drive`, `sim_rest`, `sim_tilt`, `sim_tilt_angle`, `draw_exercise_pars`, `sim_exercise`

**`model/synthetic_data.R`**: CSV writers for simulated recordings with known ground truth, in two formats  
`write_fantasia_csv`, `write_prcp_csv`, `write_tmst_csv`, `write_synthetic_data`

### `R/signals/`: what is computed from RR series and states

**`signals/events.R`**: event detection from heart rate alone (rest / perturbation / recovery)

**`signals/hrv.R`**: conventional HRV comparators and the CWT band power used for temporal resolution  
`rr_tachogram`, `band_power`, `hrv_metrics`, `cwt_band_series`, `first_departure`

**`signals/landscape.R`**: the occupied region of the (x_p, x_s) plane as an energy landscape  
`series_phases`, `normalized_path`, `landscape_limits`, `weighted_density`, `density_basins`, `density_landscape`, `flow_field`, `phase_modes`, `pooled_phase_landscapes`

**`signals/physiology.R`**: analyses that use the optional covariates (tilt angle, blood pressure, respiration)

## 3. Other folders

- `config.R`: every setting (seed, data folders, windows, event definitions, workload, figures). `pipeline.R`: the steps above as data.
- `engine/`: `model_engine.R` (the estimation engine, used unmodified) and `fast_filter.cpp` (a verified C++ port of its filter).
- `tools/`: `prep-data.R` (raw WFDB / text files -> CSV recordings and `data/prep_qc.csv`), `run_all.R` (the pipeline), `check_env.R`, `make_docs.R`, `check_figure_fonts.R`, `check_figure_rendering.R`.
- `tests/`: `run_tests.R` runs the suites: `test_workflow.R` (structure and bookkeeping), `test_pipeline.R` (unit checks, optional end-to-end run), `test_narrative.R`, `test_prep.R` (`prep-data.R` on synthetic WFDB records), `test_edge_cases.R` (absent covariates); `compare_results.R` compares two `results/` folders.
- `manuscript/`: `manuscript.qmd`, `supplementary.qmd`, `figures/`, `templates/` and `support/`. The `.qmd` files read `results/*.rds`.
- `results/`: what the pipeline writes, plus `run_log.csv`, `provenance.txt` and `MANIFEST.csv` (what was run, with which code and data, and the md5 of every file).
